# 架构决策记录

以下决策描述当前采用的实现，而不是待执行的计划。修改决策时同步实现、协议、迁移和验证记录。

## ADR-001：单 Edge，Control 与数据引擎分进程

**状态：采用。** 内部统一管理只有一个 Edge，控制进程维护数据库和管理连接，Edge 独立承载业务。这样停止控制端不必关闭有效数据连接。

代价是没有 Edge 高可用，且 Control 与 Edge 的授权传播具有短暂协调延迟。引入多 Edge 或多个 Control 前，需要先设计会话归属、选主、授权传播和故障语义，不能只增加副本数。

## ADR-002：设备内嵌 GOST Runtime，Visitor 保持官方程序

**状态：采用。** 客户端使用一个进程管理多个独立 job，直接复用 GOST listener/connector/handler/service。避免通过定期杀死子进程统一重建全部隧道，便于差异应用与精确事件。

Visitor 固定以官方 gost v3.3.0 验证；服务端与客户端的小范围补丁不能改变其线上协议。升级基线需要完整互通与撤销测试。

## ADR-003：独立管理 WSS 与数据 WSS

**状态：采用。** `/agent/v1/ws` 承载身份和配置，`/ws` 承载 GOST 数据。管理断线不关闭 Runtime，避免控制可用性变成每条现有业务连接的强依赖。

代价是必须分别展示管理在线、配置确认与数据状态，并分别维护重试。

## ADR-004：结构化固定目标与角色授权

**状态：采用。** 隧道目标由管理员配置，设备只接收结构化 TCP/UDP IPv4 参数。Provider 仅 Bind，Visitor 仅 Connect；设备忽略 Visitor 拨号目标。

这限制了原生 GOST 的任意路由能力，但提供了可审计授权边界。未来扩展域名、IPv6 或其他协议时，应先定义目标解析和授权语义。

## ADR-005：完整快照、版本/hash、持久协调

**状态：采用。** 事务内保存资源、快照、operation/outbox 和审计。先确认 Edge 策略，再下发设备配置；离线设备用最新快照收敛。

完整快照简化重放和断线恢复，代价是序列化与投递量随配置规模增加。需要增量协议时，仍应保留可恢复的完整快照与一致性检查。

## ADR-006：JSONB 实体表与聚合串行写

**状态：采用。** 使用 PostgreSQL 的关系约束保护主要关联，JSONB 保持模型明确；advisory lock 串行化状态变更。

代价是大聚合的读/序列化/写锁成本；当前 sqlc 不是全部资源 CRUD。资源规模显著增加或写入延迟超标后，应根据负载结果拆分为资源级 SQL，而非先宣称无限扩展。

## ADR-007：秘密可再次展示

**状态：采用。** Visitor 秘密同时保存摘要与 AES-GCM 密文，管理员可以再次获取命令/YAML，展示留审计。

代价是 Vault 主密钥成为恢复必需材料。若未来改为一次展示，应重新设计凭据轮换和管理体验，不能只删除解密入口。

## ADR-008：精确 5 倍退避

**状态：采用。** 独立持久计数执行 5、25、125、625、3125 秒封顶，无最大次数，完整认证/Bind 成功清零。

恢复可能等待约 52 分 5 秒。当前没有随机抖动，也不把进程崩溃重启机制当成网络重试。改变数列或增加 jitter 都属于行为变更，需要更新约束与测试。

## ADR-009：反代产品与数据库体系由使用者决定

**状态：采用。** 程序默认暴露 loopback HTTP/WS 与受限内部接口，不负责签发证书或管理外部数据库。文档首先提供最小启动和路径/Host/WebSocket 契约。

`deploy/openresty.conf`、systemd unit 和可丢弃安装验收是集成示例，不要求用户替换现有基础设施。容器业务入口通过显式 `--allow-non-loopback` 接入 Docker 私网或回环端口发布，内部管理入口保持受限，不把 HTTP/WS listener 直接当作公网 TLS 服务。

## ADR-010：单镜像、双进程的服务端容器

**状态：采用。** 一个镜像包含 Control、Edge、Web 和 Go 编写的进程管理入口，不引入容器内数据库、反向代理、systemd 或 shell。Compose 默认非 root、只读根文件系统，业务端口仅发布至宿主机回环地址，内部通信使用 Unix socket；密钥和策略快照使用持久卷。

初始化、迁移和管理员创建均为显式管理命令。正常启动缺少有效密钥时拒绝运行，不自动重置数据库或身份。入口负责信号转发、等待与超时终止，任一服务退出时停止另一个并让容器失败退出。

代价是两者共享故障恢复与升级边界，Control 故障也会使数据面重启。需要单独维护 Control/Edge 生命周期时仍可使用已有二进制部署，不将单容器解释为高可用。
